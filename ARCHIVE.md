# Private article archive

Package on a trusted workstation. Keep the source HTML, media and manifest in a
private directory outside all Git checkouts. Use a unique passphrase generated by
a password manager or a randomly generated multiword passphrase. Store it in the
password manager and use its secure sharing feature if readers need it. Type it
only into the hidden local prompt and the archive's unlock field on a trusted
copy of the site. Public ciphertext can be downloaded and guessed against offline.

Install the packaging dependencies in an isolated Python environment. Run these
commands from the checkout root, with the manifest and output elsewhere:

```sh
python3 -m venv /path/to/private/archive-venv
/path/to/private/archive-venv/bin/python -m pip install 'cryptography>=44,<51' 'lxml>=5,<7'
/path/to/private/archive-venv/bin/python tools/package_archive.py build /path/to/private/manifest.json /path/to/private/new-archive-data
```

The output directory must be new. The builder uses PBKDF2-HMAC-SHA-256 with
600,000 iterations and a random 16-byte per-build salt. It encrypts the index, each
article and each asset with AES-256-GCM, random 12-byte nonces and record names
authenticated as associated data. The archive format exposes file counts and
sizes. Each build refreshes the salt, nonces and opaque record names.

Keep a manifest like this in the private directory. Paths are relative to the
manifest. Use the exact source `src` attribute as the asset mapping key.

```json
{
  "articles": [
    {
      "clip": "source.html",
      "publisher": "Publication Name",
      "date": "2025-01-01",
      "assets": {
        "./Original graphic.png": "media/graphic.png"
      }
    }
  ]
}
```

The packager preserves article content beginning at the first headline, keeps
captions and HTTP(S) source links, and filters markup to supported elements.
Supply local copies of permitted media. Missing media gets an inline
placeholder. For an existing Flourish visualization, confirm reuse permission
and test its public embed URL before adding its provider ID (for example,
`visualisation/123`) to the article's optional `flourish` array. Readers load
each allowed embed by selecting its Flourish button.

To add an article, add its clip, metadata and any approved media to the private
manifest and build a fresh bundle for the entire archive. Move the previous
`site/archive-data` directory out of the checkout if present, then copy the new
ciphertext directory to `site/archive-data`. Stage only the intended files,
inspect the entire staged change and check the exported artifact:

```sh
git diff --cached --name-status
python3 tools/check_pages.py --staged /path/to/private/new-pages-artifact
/path/to/private/archive-venv/bin/python tools/package_archive.py verify /path/to/private/new-pages-artifact/archive-data
python3 -m http.server 8000 --bind 127.0.0.1 --directory /path/to/private/new-pages-artifact
```

The verify command authenticates every record, including the encrypted index and
its references. Try a wrong passphrase, then use the production passphrase to
open every clip and its media in the browser. Stop the server after testing. The
Pages workflow exports the committed `site/` tree with the same artifact checker
and uploads that checked directory. After deployment repeat the unlock test on
the live HTTPS site and compare the served ciphertext to the locally verified
artifact. Share only the encrypted bundle and verification outcome with a
collaborator. Rotating a passphrase cannot revoke older ciphertext copies.
